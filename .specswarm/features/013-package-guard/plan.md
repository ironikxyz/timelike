## Summary

One new agent tool, **`tools/bin/package-guard`** (spec FR-1 to FR-36). It reads an install command, finds
the registry the installer would use, checks each named package:
- that it exists;
- that its release is at least the minimum age;
- whether the project's lockfile already pins it.

It then runs the command through `run`, or refuses with 001's `confirmation_required` envelope. Its `--yes`
proceeds and writes an override record that the tool's session event points at.

**Tests:**
- A registry stand-in, **`tests/fixtures/registry-standin.py`**, serves PyPI's Simple API and npm's registry
  shapes (research R2), and logs every request.
- The host units run the host's real `pip`, `npm` and `pnpm` against it.
- The e2e files run the image's real `pip`, `uv` and `npm` against it inside the agent container.

**Held for FOR-MENTOR Item 24, raised before this is built:** how the bare `pip`/`npm`/`uv`/`pnpm` reach the
tool (seam 1), adding pnpm to the image (seam 2), and the event-field alternative (seam 7).
- **Nothing is added to the image** but the tool itself: one file in `tools/bin`, which the Dockerfile
  already copies whole.
- **Nothing is added to compose.**
